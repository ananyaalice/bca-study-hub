Chapter 18 : I/O Devices

  • I/O = Input / Output. Lets the computer communicate with the outside world
  • Input devices send data to the computer. Output devices receive data from the computer
  • Essential for user interaction and data processing

18.3 External (auxiliary) storage devices

  • Store data outside the computer. Portable and easy to use
  • Examples: pen drives (USB flash drives), external hard drives (HDD / SSD), memory cards, CDs / DVDs, cloud storage (Google Drive, OneDrive)

18.4 Why I/O systems are important

  • Help users communicate with the system
  • Enable data entry and display
  • Support external storage and backups
  • Improve usability and accessibility
  • Essential for all computer operations

18.5 I/O and computer performance

  • Factors: processor speed (clock speed, cores); RAM capacity; storage type (SSD > HDD); graphics ability; I/O device speed; system architecture and OS efficiency
  • Fast I/O → less waiting. Slow I/O → bottlenecks
  • Examples: SSD loads faster than HDD; high-resolution monitors need a better GPU; USB 3.0 transfers faster than USB 2.0
  • Performance also depends on buffering, spooling, interrupt handling

Chapter 19 : I/O Control Mechanisms

  • They decide how data moves between I/O devices and the CPU / memory. Three: 1 Polling (programmed I/O), 2 Interrupts (interrupt-driven I/O), 3 DMA (direct memory access)

19.1 Polling (programmed I/O)

  • CPU continuously checks the status of an I/O device and waits until it is ready – busy waiting
  • Features: simple to implement; CPU fully involved; suitable for simple or slow devices
Advantages
  • Easy to understand and implement
  • Good for simple systems
  • No complex hardware
Disadvantages
  • Wastes CPU time
  • CPU busy even if no task
  • Low efficiency for fast systems
  • Performance bottlenecks

19.2 Interrupts (interrupt-driven I/O)

  • Interrupt = a signal from a device to the CPU. CPU stops its current task temporarily, handles the I/O request, then returns to the previous task
  • Used for devices needing quick attention – e.g. keyboard key press
Device sends interrupt signal→CPU pauses current program→CPU saves its state→Executes Interrupt Service Routine (ISR)→Completes I/O task→Returns to original program
  • Benefits: CPU is not busy-waiting; more efficient than polling
Type of interruptMeaning and example
HardwareTriggered by external devices – keyboard, mouse, printer, network card
SoftwareGenerated by programs or OS – system calls
TimerGenerated at regular intervals – time-sharing, scheduling
Advantages
  • Saves CPU time
  • Faster response
  • Better performance
  • Good for multitasking
Disadvantages
  • Needs extra hardware
  • More complex to implement
  • Too many interrupts → interrupt storm

19.3 Direct Memory Access (DMA)

  • I/O devices transfer data directly to main memory; the CPU is bypassed during transfer
  • A special hardware – the DMA controller – manages the transfer. Very fast; used for high-speed devices (disk, network, graphics)
CPU gives DMA controller: memory address, device address, amount of data→DMA controller starts transfer→CPU continues other tasks→DMA sends an interrupt when transfer is complete
  • Outcome: fast, efficient transfer; CPU involvement minimal
  • Used for: disk read / write; audio / video streaming; network data transfer; large memory block copying
  • Why: removes CPU bottleneck, reduces delay, improves performance

Polling vs Interrupts vs DMA

FeaturePollingInterruptsDMA
CPU involvementVery highModerateVery low
SpeedSlowFasterFastest
Best forSimple devicesMedium-speed devicesHigh-speed transfers
Hardware requirementLowMediumHigh
EfficiencyLowGoodExcellent

Chapter 20 : Buses and I/O Ports

  • Buses and I/O ports are the pathways and connection points for communication between CPU, memory and peripherals

20.1 Bus

  • Bus = a shared communication pathway that transfers data, addresses and control signals; connects CPU, memory and I/O devices
BusCarriesDirection
Data busActual data between CPU, memory and I/O devicesBidirectional
Address busMemory addresses from CPU to memory / I/O devicesUnidirectional
Control busControl signals (read, write, interrupt). Manages transfer operations—
  • Importance: communication between internal components; decides system performance (speed and bandwidth); the “highway” for data; supports expansion

20.2 I/O ports

  • I/O ports = interfaces that connect the CPU to external devices; entry / exit points for data. Let the CPU send commands and receive data from peripherals
PortMeaning
SerialSends data one bit at a time. E.g. USB, RS-232
ParallelSends many bits at the same time. E.g. printer port (older systems)
USBUniversal interface for modern devices
  • Role: connect keyboard, mouse, printer etc.; controlled communication with CPU; device-specific data transfer; enable input and output

20.3 Buses and ports together

  • CPU sends addresses on the address bus → data moves on the data bus → control bus gives proper timing → I/O ports are the interface for devices to send / receive data through the bus
User presses a key→Keyboard sends signal to its I/O port→CPU receives data via data bus→CPU processes it, sends output to display through display port

Chapter 21 : Performance Metrics

  • Evaluate speed and efficiency of a computer. Common metrics: clock cycles, execution time, throughput, latency
MetricMeaningFormula / examples
Clock cycleSmallest unit of time in which a processor does a basic operation. Measured by clock speed (e.g. 3 GHz). Higher clock speed → more cycles per second → fasterCPU Time = Number of Clock Cycles × Clock Cycle Time. Helps compare processors
Execution timeTotal time a system takes to complete a program. Includes CPU time + other delays (memory, I/O). Lower = fasterExecution Time = Number of Instructions × CPI × Clock Cycle Time
ThroughputNumber of tasks completed per unit time (tasks/sec, requests/sec). High = can handle more workloadWeb server 500 requests/sec; CPU executing many instructions per cycle (IPC); network moving 1 GB per minute
LatencyTime delay between a request and its response. How quickly the system reacts. Seen in memory access, networking, I/OTime to fetch data from RAM; delay between clicking a link and the page loading; time from sending a packet to getting a response
  • CPI = clock cycles per instruction (average cycles one instruction needs). Clock cycle time = 1 / clock speed
  • Why execution time matters: shows real-world performance; used to judge algorithms, compilers and hardware upgrades
  • Example (textbook style): 1000 instructions, CPI = 2, clock 2 GHz (cycle time 0.5 ns) → 1000 × 2 × 0.5 ns = 1000 ns = 1 µs

Throughput

How much work is done

Latency

How fast a single task is completed
  • A system can have high throughput but high latency, or low latency but low throughput. Both must be optimised

Chapter 22 : RISC vs CISC

  • CPU architectures decide how instructions are designed and executed. Two approaches: RISC and CISC. Goal: better efficiency and performance
RISC – Reduced Instruction Set ComputerCISC – Complex Instruction Set Computer
IdeaSmall, simple set of instructions. Focus on speed and efficiencyLarge set of complex instructions. One instruction can do multiple operations. Focus on fewer instructions per program
ExecutionEach instruction usually one clock cycleInstructions may take multiple clock cycles
Key featuresSimple, uniform instructions • Larger number of registers • Load/store architecture (memory accessed only by load and store) • Hardwired control unit (faster) • Easy pipeliningMany instructions, varied formats • Memory-to-memory operations allowed • Microprogrammed control unit • More addressing modes
AdvantagesFaster execution • Better pipeline performance • Lower power • Suited to mobile and embedded devicesCompact programs (fewer instructions) • Better for complex tasks • Easier compiler design • Good for desktop and server processors
ExamplesARM (mobiles / tablets), MIPS, RISC-V, SPARCx86 (Intel, AMD), VAX, System/360

★ Key Observations

  • Polling = CPU keeps checking; interrupt = device calls the CPU; DMA = device talks to memory directly
  • CPU involvement: polling very high → interrupt moderate → DMA very low
  • Address bus is unidirectional; data bus is bidirectional
  • Serial = 1 bit at a time; parallel = many bits at once
  • Latency = speed of one task; throughput = amount of work
  • RISC = simple, 1 cycle, many registers, load/store; CISC = complex, multi-cycle, fewer instructions
  • Slow I/O causes bottlenecks; DMA and interrupts reduce them

Real-Life Applications

  • Keyboard and mouse use interrupts; disk and video streaming use DMA
  • Dot-matrix printers for bills; laser for offices; inkjet for colour
  • USB 3.0 – faster file transfer than USB 2.0. SSD – faster loading than HDD
  • Web servers – throughput in requests/sec; games / web pages – low latency
  • ARM (RISC) in phones; x86 (CISC) in PCs and servers

Chapter 9 : Architecture of the CPU

  • CPU = the brain of the computer. It fetches, decodes and executes instructions
  • Main parts: ALU, Control Unit (CU), Registers, Buses (+ cache)
Memory / I/O↔BUSES
(data, address, control)↔REGISTERS↔ALU↕CONTROL UNIT
(signals to all parts)

9.1 ALU (Arithmetic and Logic Unit)

  • Does arithmetic (add, subtract, multiply, divide) and logic (AND, OR, NOT, comparison) and shift operations
  • Takes operands from registers; result goes to a register (e.g. accumulator)
  • Sets status flags – e.g. zero, carry, sign (negative), overflow – used by branch instructions

9.2 Control Unit (CU)

  • Directs the whole CPU. Fetches instructions, decodes them and sends control signals (clock, read, write, etc.) to ALU, registers, memory and I/O
  • Makes all parts work together in correct timing
  • Two designs: Hardwired (logic circuits – fast, used in RISC) and Microprogrammed (control memory – flexible, used in CISC)

9.3 Registers

  • Small, very fast storage inside the CPU. Hold data, instructions and addresses being used

Chapter 11 : Machine-Level Programming and Assembly Language

  • Machine language = instructions in binary (0s and 1s) that the CPU understands directly. Depends on the CPU; hard to write and debug
  • Assembly language = low-level language using short mnemonics (symbolic codes) instead of binary
  • An assembler translates assembly code into machine code. Usually one assembly instruction = one machine instruction
  • Both are machine-dependent (different for x86, ARM etc.)
MOV AX, 5      ; copy 5 into register AX
ADD AX, 3      ; AX = AX + 3  → 8
; machine code example (x86): MOV AL, 61h  →  B0 61 (hex)

Chapter 12 : Instruction Set Architecture (ISA) in CPU Design

  • ISA = the interface between software and hardware. It lists what instructions the CPU can execute and how programmers use the CPU
  • The ISA defines: instruction set, data types and formats, registers, addressing modes, instruction format and length, memory model, I/O handling
  • Microarchitecture = how the ISA is built inside the CPU (pipeline, cache, data paths)
Instruction typeExamples

Role of ISA in CPU design

  • Fixes what the hardware must do – decides registers, control unit and ALU needed
  • Software compatibility – programs run on any CPU with the same ISA (e.g. x86 family) even if the hardware inside differs
  • Performance trade-off – a simple ISA is easier to speed up; a rich ISA gives compact programs

Chapter 13 : Caching and Pipelining

13.1 Caching

  • Cache = small, very fast SRAM memory between the CPU and RAM. Stores frequently used data and instructions, so the CPU waits less
  • Works because of locality of reference: temporal – recently used data is used again soon; spatial – nearby addresses are used soon
  • Levels: L1 (fastest, smallest, in the CPU) → L2 (larger, slower) → L3 (larger, shared across cores)
  • Cache hit = data found in cache (fast). Cache miss = not found → fetched from RAM (slow)
  • Hit ratio = hits ÷ total accesses
Average memory access time = Hit time + Miss rate × Miss penalty
Example: hit time 1 ns, miss rate 10 % (0.1), miss penalty 100 ns → 1 + 0.1 × 100 = 11 ns
  • Textbook points: mapping – direct, associative, set-associative; replacement – LRU, FIFO; write policy – write-through, write-back

13.2 Pipelining

  • Pipelining = the CPU starts the next instruction before the current one finishes – like a factory assembly line. Several instructions are in different stages at once
  • Classic 5 stages: IF instruction fetch → ID decode → EX execute → MEM memory access → WB write back
Instr.12345678
I1IFIDEXMEMWB
I2IFIDEXMEMWB
I3IFIDEXMEMWB
I4IFIDEXMEMWB
k stages, n instructions: without pipeline = n × k cycles; with pipeline = k + n − 1 cycles.
Example: k = 5, n = 4 → 20 cycles vs 8 cycles. Speed-up = 20 ÷ 8 = 2.5 (approaches k for large n).
  • Pipelining raises throughput (instructions per unit time). One instruction’s own time (latency) does not shrink
Pipeline hazardCauseFix
StructuralTwo instructions need the same hardware at onceMore hardware / stall
DataAn instruction needs a result not yet producedStall (bubble), forwarding
ControlBranch – next instruction not knownBranch prediction, stall
  • RISC (simple, fixed-length instructions) is easy to pipeline. Cache and pipelining reduce the Von Neumann bottleneck

★ Key Observations

  • CPU = ALU + CU + registers + buses
  • PC holds the next instruction address; MAR = address; MDR = data; IR = current instruction
  • Address bus width n → 2ⁿ memory locations
  • Instruction cycle: Fetch → Decode → Execute → Store. Fetch increments the PC
  • Machine language = binary. Assembly = mnemonics + assembler
  • ISA = software–hardware interface. Microarchitecture = its implementation
  • Cache hit = fast, miss = slow. Pipelining overlaps instructions

Real-Life Applications

  • Assembly – embedded systems, device drivers, OS kernels
  • ISA compatibility – the same software runs on different x86 PCs; ARM in phones
  • Cache – faster apps and games on the same CPU
  • Pipelining – modern CPUs finish about one instruction per cycle

★ Exam Points ★

  • CPU parts: ALU, control unit, registers, buses. Buses: data, address, control
  • Registers: PC, IR, MAR, MDR, AC, general-purpose, flag, stack pointer
  • Control unit types: hardwired and microprogrammed
  • Instruction cycle: fetch, decode, execute (store result)
  • Fetch: MAR ← PC; MDR ← Memory[MAR]; IR ← MDR; PC ← PC + 1
  • Machine language = binary; assembly = mnemonics, translated by an assembler
  • ISA = interface between software and hardware; gives software compatibility
  • Cache = fast SRAM between CPU and RAM; L1, L2, L3; uses locality of reference
  • Average access time = Hit time + Miss rate × Miss penalty
  • Pipeline: IF, ID, EX, MEM, WB; cycles = k + n − 1; hazards: structural, data, control

Chapter 14 : Types of Memory

  • Memory hierarchy = arrangement of memory components by speed, cost and size
  • Top to bottom: Registers → Cache → RAM → Secondary storage (HDD / SSD)
  • Goal: high speed at low cost
Registers
Cache
RAM
HDD / SSD

Top: fastest and smallest (registers, cache) → bottom: slowest and largest (RAM, HDD / SSD)

Why a hierarchy?

  • CPU is very fast; memory is slower
  • Direct access to slow memory reduces performance
  • Solution: multiple levels of memory – balance speed, capacity and cost
Types of memory→1 Primary: RAM, ROM|2 Cache memory|3 Secondary storage: HDD, SSD

14.1 RAM (Random Access Memory)

  • Volatile – data lost when power is off. Temporary storage for programs and data. Used by CPU for quick access
  • DRAM (Dynamic RAM) – slower, cheaper. SRAM (Static RAM) – faster, costlier, used in cache
  • Features: read / write capability; faster than secondary memory; more RAM → better system performance; e.g. 4 GB, 8 GB, 16 GB

14.2 ROM (Read-Only Memory)

  • Non-volatile – keeps data after power off. Holds permanent instructions used during booting. Cannot be easily modified
PROMProgrammable once
EPROMErasable using UV light
EEPROMElectrically erasable
Flash ROMUsed in pen drives, BIOS

14.3 Cache memory

  • Very fast memory located inside the CPU. Stores frequently used data and instructions. Reduces CPU waiting time. Uses SRAM
L1Fastest, smallest, inside the CPU
L2Larger, slower than L1
L3Shared across cores, larger

14.4 Registers

  • Smallest and fastest memory, inside the CPU. Hold data / instructions being processed
  • Size: few bytes to few KB. Access time: less than a nanosecond
  • Examples: Program Counter (PC), Accumulator, Instruction Register (IR)

14.5 Main memory (RAM)

  • Also called primary memory. Stores data and programs currently in use
  • Faster than secondary storage, slower than cache and registers. Volatile. Common sizes: 4 GB – 32 GB

14.6 Secondary storage

  • For long-term data storage. Two types: HDD and SSD

HDD (Hard Disk Drive)

  • Fixed secondary storage device inside computers. Uses magnetic technology. Non-volatile. Stores OS, applications, files, documents
  • Data stored in sectors on rotating platters. Read/write head moves over the spinning platters. Correct head positioning decides access speed
  • Outer and inner tracks hold the same number of sectors (storage density differs)
HDD partWork
PlattersGlass / aluminium disks coated with magnetic material
SpindleHolds and rotates the platters (5400–15000 RPM)
Actuator armMoves the read/write heads precisely
Read/write headDoes the actual reading and writing
Controller boardManages data flow between drive and computer
  • Features: non-volatile; high capacity (up to 36 TB); mechanical (moving parts); relatively slow (access time in milliseconds); cost-effective (cheaper than SSD); reliable, widely used in enterprise storage
  • How HDD works: platters spin (5400–15000 RPM) → heads move to the correct track → magnetic signals read / written as platters rotate → disk controller transfers data to the computer → heads and platters keep moving to access data

SSD (Solid State Drive)

  • Stores data using NAND flash memory. No spinning disks, no mechanical heads
  • Faster, more durable, quieter than HDD → faster boot, file loading and applications
  • How SSDs work (data stored in cells, pages and blocks):
Controller chipManages how data is stored, retrieved and optimised
Wear levelingSpreads write / erase cycles evenly over blocks → longer life
Garbage collectionConsolidates empty blocks to keep performance high
TRIM commandTells SSD which blocks are no longer needed → faster, fewer unnecessary writes
Error correction (ECC)Detects and fixes errors → data accuracy
Data compressionSaves space and boosts performance
  • Features of SSD: fast start-up; quick access (low read latency, fast random access); speed about 100–600 MB/s; no fragmentation; silent; reliable (less wear); wide temperature support; shock resistant (good for laptops); faster boot / load; better security (hardware encryption, secure erase)

Types of SSD

PCIe-based SSDUses PCIe; very fast read / write, low latency
NVMe SSDNVMe protocol over PCIe; ultra-fast (3000+ MB/s); gaming and performance tasks
Flash DIMMsSSD in DIMM (RAM-like) form; faster than PCIe SSD; needs special drivers and motherboard support
Hybrid DRAM–FlashFlash + DRAM; balanced speed, performance, capacity

Virtual memory (overview)

  • Technique that extends RAM using part of the hard disk / SSD. Lets large programs run even if RAM is full
  • Implemented using paging. Slower than RAM (storage is slower). Prevents freezing or crashing when RAM is short

Chapter 17 : Memory Management and the MMU

17.1 Memory management

  • = controlling and coordinating the computer’s memory (RAM). Ensures programs get memory when needed; do not use others’ memory; memory used efficiently; no crash from memory problems
  • Why needed: run many processes at once (multitasking); avoid wastage; keep each process safe; improve performance
ActivityMeaning
AllocationGiving memory to processes when they ask
DeallocationFreeing memory after a process finishes
ProtectionOne program cannot access another’s memory
Address translationLogical address → physical address

  • Also called virtual address
Physical address

  • Used by hardware

Memory allocation techniques

ContiguousMemory given in one continuous block. Advantages: simple, fast. Disadvantage: fragmentation
Non-contiguousProgram divided into parts, stored in different locations: Paging, Segmentation, Paging + Segmentation. These support virtual memory

17.2 Virtual memory

  • Lets programs use more memory than the physical RAM
  • Benefits: run large programs on small RAM; multitasking; memory protection; prevents system crashes
  • Works: program divided into fixed-size pages; RAM divided into frames; only required pages kept in RAM; rest stay on disk
  • Page fault = required page is not in RAM → OS loads it from disk

Paging

  • Memory divided into frames (fixed size)
  • Process divided into pages (same size)
  • Pages can go into any free frames
  • MMU keeps a page table
  • ✔ No external fragmentation ✔ Efficient use of memory

Segmentation

  • Memory divided by logical divisions – code, data, stack, heap
  • Each segment has variable size
  • E.g. Segment 0 = Code, Segment 1 = Data, Segment 2 = Stack

17.3 Memory Management Unit (MMU)

  • Hardware component between the CPU and RAM. Does address translation and memory protection
FunctionMeaning
1 Address translationLogical (virtual) → physical address using page tables
2 Memory protectionStops one process using another’s memory. If process A tries to access process B’s memory → MMU blocks it
3 Paging and segmentation supportUses page tables and segment tables
4 Caching controlDecides which data can be cached for faster access
5 Handling page faults (with OS)Page missing from RAM → MMU notifies the OS

★ Key Observations

  • Higher in the hierarchy = faster, smaller, costlier. Lower = slower, larger, cheaper
  • RAM and cache are volatile; ROM, HDD, SSD are non-volatile
  • Cache uses SRAM; main memory uses DRAM
  • HDD = moving parts, cheap, large. SSD = no moving parts, fast, quiet, shock resistant
  • Indirect addressing needs two memory accesses
  • Paging → fixed-size pages and frames. Segmentation → variable-size logical parts
  • CPU makes logical addresses; RAM uses physical addresses; MMU converts

Real-Life Applications

  • More RAM → smoother multitasking. SSD → faster boot and app loading
  • Flash ROM / BIOS and pen drives; ROM holds boot instructions
  • HDD – large, cheap backups and archives. NVMe SSD – gaming
  • Indexed addressing – looping through arrays. Relative – jumps and loops
  • Virtual memory – running big programs on small RAM

★ Exam Points ★

  • Hierarchy: Registers → Cache → RAM → Secondary (HDD / SSD). Goal: speed at low cost
  • RAM volatile (DRAM, SRAM). ROM non-volatile: PROM, EPROM, EEPROM, Flash
  • Cache: SRAM; levels L1, L2, L3
  • HDD parts: platters, spindle, actuator arm, read/write head, controller board; 5400–15000 RPM
  • SSD: NAND flash, no moving parts; wear leveling, garbage collection, TRIM, ECC
  • SSD types: PCIe, NVMe, Flash DIMM, Hybrid DRAM–Flash
  • Addressing modes: direct, indirect, indexed, relative. Indexed: Base + Index. Relative: PC + Offset
  • Memory management: allocation, deallocation, protection, address translation
  • Allocation: contiguous and non-contiguous (paging, segmentation)
  • Virtual memory: pages + frames; page fault → OS loads page from disk
  • MMU: address translation, protection, paging / segmentation support, caching control, page fault handling
